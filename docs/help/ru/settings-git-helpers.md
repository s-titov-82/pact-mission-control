# Git-попап

Этот раздел настраивает всплывающее меню ⎇ панели git проекта и разделён на две верхнеуровневые вкладки: Buttons (что запускают собственные кнопки-команды попапа) и External helpers.

Вкладка Buttons. У простых встроенных кнопок (Pull, Stash, Pop stash) редактируется Command — полная строка аргументов git; кавычки группируют слова, ведущее «git » допускается. Диалоговые кнопки (Commit, Push, Switch, Rebase, Merge) получают аргументы из своих диалогов, поэтому редактируется только Extra flags: фиксированные флаги, вставляемые сразу после субкоманды git (например --no-ff для merge, --autostash для rebase); read-only строка предпросмотра показывает, куда они попадают. У каждой встроенной кнопки есть переключатель Enabled — выключенная кнопка скрывается из попапа — и нет удаления: встроенные можно только выключить, и даже запись, удалённая из сырого JSON, молча откатывается к встроенному дефолту (вкладка появится снова с дефолтами при следующей загрузке). «+» добавляет пользовательскую запись: она становится дополнительной кнопкой попапа, выполняющей свой Command как есть, и, в отличие от встроенных, её можно удалить. Кнопки ◀/▶ рядом с «+» перемещают выбранную вкладку на один слот влево или вправо — это переставляет и кнопки в попапе, так как порядок вкладок совпадает с порядком отрисовки кнопок. Сценарий «Rebase onto base» переиспользует настроенную команду Pull и extra-флаги Rebase.

Вкладка External helpers. Каждая запись — это интеграция с одним внешним git GUI-инструментом; его кнопки показываются в том же попапе, но только когда инструмент действительно определяется (resolve) на этой машине — помощник, который не определился, не добавляет ни одной кнопки и вообще не показывается.

Порядок определения Executable: абсолютный путь, существующий на диске, используется как есть; иначе в Windows считывается пара «ключ/значение реестра» (проверяются оба представления реестра — 64- и 32-битное) и используется, если она указывает на существующий файл; иначе имя исполняемого файла ищется в PATH. Если ни один из способов не приводит к существующему файлу, помощник скрывается.

У каждого действия всплывающего меню есть Slot, определяющий, где оно показывается:

- history — кнопка истории/лога в списке действий всплывающего меню.
- custom — дополнительная кнопка команды, показывается рядом с history в том же списке.
- resolve — действие разрешения конфликтов панели; используется только первое действие с этим slot. Если ни один помощник не определяет действие resolve, «Resolve» откатывается на прямой запуск «git mergetool -y».
- любое другое значение slot нигде не показывается и фактически игнорируется.

Arguments (по одному в строке) могут использовать плейсхолдеры {root} и {branch}, которые подставляются путём корня проекта и именем текущей ветки при запуске действия.

Внешние инструменты, которые стоит подключить таким образом: TortoiseGit, Fork, SourceTree, GitExtensions — у каждого есть собственные ключи командной строки для открытия просмотра лога или средства разрешения конфликтов, которые нужно перевести в Arguments действия.
