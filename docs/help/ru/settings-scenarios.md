# Сценарии

Сценарий автоматизирует цикл ревью между двумя работающими сессиями терминала: автором и ревьюером. Сценарий запускается одиночным кликом по его кнопке в списке «Scenarios» главного окна; далее диалог настройки привязывает роли автора и ревьюера к реально работающим сессиям и позволяет задать цель ревью (указатель области или вставленный текст) перед началом запуска.

Каждое определение сценария здесь — это «review-loop»: ревьюер проверяет работу автора на наличие стоп-маркера в течение не более чем Max iterations проходов, используя четыре шаблона запроса в фиксированном порядке:

- Start prompt template — отправляется ревьюеру для прохода 1; содержит полное задание на ревью (цель, критерии, правила маркера).
- First feedback template — отправляется автору после прохода 1, содержит замечания ревьюера.
- Author return template — отправляется ревьюеру для проходов 2..N, содержит ответ автора для повторной проверки.
- Feedback template — отправляется автору для проходов 2..N, содержит очередные замечания ревьюера.

Завершение определяется по полному файлу ответа ревьюера с корректным
транспортным footer: как только такой ответ содержит точный текст Stop marker,
запуск завершается успешно — другого автоматического условия успеха нет.
Состояние терминального экрана и захваченный вывод сами по себе проход не
завершают. Если проходит Max iterations проходов без появления маркера, запуск
останавливается как незавершённый.

Reviewer instructions — это произвольные текстовые пресеты, а не фиксированный список дисциплин; добавляйте и удаляйте их кнопками +/− рядом со списком, редактируя у каждого пресета Id, Name и Text. Default reviewer instruction определяет, какой пресет будет выбран по умолчанию при настройке запуска этого сценария.

Default target задаёт начальное значение поля цели ревью в диалоге настройки; для конкретного запуска его всё равно можно переопределить.

Пока запуск активен, обе участвующие сессии заблокированы для ввода — печатать
в них нельзя, но их вывод остаётся видимым и прокручиваемым. Ручная пауза
(Manual Pause) разблокирует обе сессии и запрещает новые автоматические записи
в терминалы до Resume; если во время паузы появляется корректный файл ответа,
запуск продвигается и снова блокирует сессии без Resume. Если watchdog
приостанавливает запуск из-за того, что сессия выглядит зависшей,
разблокируется только эта сессия, чтобы можно было ответить вручную и
продолжить запуск.

Каждый запуск ведёт журнал только в памяти, пока его можно открыть в панели журнала. После закрытия запуска журнал удаляется; на диск в data-root журналы сценариев не записываются.
