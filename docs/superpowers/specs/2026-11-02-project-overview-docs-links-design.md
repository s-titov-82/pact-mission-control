# Единый экран проекта: Overview, Docs и ссылки агентов

Статус: согласовано пользователем 2026-11-02; реализовано, код и проверки пройдены
2026-11-03. Визуальная проверка через computer-use не состоялась: истёк срок
ожидания доступа к тестовому окну. Изолированный native-перезапуск пройден.

## Назначение

Сделать экран проекта постоянной точкой входа: сведения о репозитории,
открытие установленных IDE, полезные ссылки и активные ревью находятся над
проектными заметками. Документация становится соседней вкладкой этого экрана.

## Согласованное с пользователем

- Порядок вкладок: **Overview · Docs · Changes · Review logs**.
- Отдельная строка `Docs & Notes` в дереве и кнопка показать/скрыть заметки
  в действиях проекта исчезают.
- Notes занимают нижние две трети области Overview и всегда доступны там.
- Вверху Overview — три строки: имя с кнопкой редактирования; путь с кнопкой
  открытия каталога; адрес Git-репозитория с кнопкой-глобусом и ветка через точку.
  Путь, адрес и ветка используют одинаковое оформление; встроенные кнопки
  выровнены по нижнему краю строки. Кнопки IDE и обновления имеют общий размер,
  обновление использует увеличенную стандартную иконку из дерева вкладок.
- Сводку изменений не дублируем: она уже находится справа. Отдельную сущность
  и счётчик замечаний в Overview не добавляем.
- В средней части допустимы активные ревью и быстрые переходы.
- IDE обнаруживаются автоматически на машине пользователя; найденные приложения
  представлены кнопками с логотипами. Ручная настройка команды для каждого
  проекта не требуется.
- Ссылки CI/MR/Issue добавляют агенты через MCP, когда создали соответствующий
  объект либо получили адрес от пользователя. Заполнение шаблонов для каждого
  проекта не является основным сценарием.

## Подходы

Для IDE пользователь выбрал автоматическое обнаружение вместо предлагаемой
ручной команды редактора. Для проектных ссылок пользователь выбрал передачу
известного адреса агентом вместо настройки шаблонов или поиска MR/Issue через
отдельные интеграции с провайдерами. Это позволяет одинаково работать с разными
Git-хостингами, CI и трекерами задач.

Предлагаемый способ реализации — переиспользовать существующие документы,
автосохранение, запуск внешних программ и MCP-персистенцию агентских файлов.
Новые журналы, классификаторы и фоновые интеграции с CI не нужны.

## Экран проекта

Верхняя треть Overview содержит сведения о проекте, быстрые переходы и краткий
список активных ревью. Нижние две трети — существующий редактор/preview Notes
с его состояниями сохранения и обработкой конфликтов. При малой высоте окна
внутреннее содержимое верхней области прокручивается, заметки сохраняют место.

В быстрых переходах показываем:

- обнаруженные IDE с логотипом и названием в подсказке;
- открытие каталога проекта в Проводнике;
- добавленные агентами ссылки с названием и значком типа.

Адрес репозитория в шапке можно открыть в браузере. Для проектов без Git
показываем имя и путь; недоступные Git-данные не подменяем старыми данными
другого проекта. Используем origin, а при его отсутствии — первый fetch remote.

Активное ревью показывает участников и текущий ход. Можно открыть участника
или соответствующий журнал. Несколько ревью одного проекта поддерживаются.
Завершённые ревью остаются во вкладке Review logs.

## Docs и Notes

Docs переиспользует существующее дерево Markdown, редактор, preview и переходы
по относительным ссылкам. Notes доступны только в Overview, отдельного раздела
Notes внутри Docs больше нет. Работающий терминал при этих переходах продолжает
работать в фоне.

Существующие тексты Notes сохраняют прежнее хранилище и идентичность документа.
Старое состояние видимости Notes больше не скрывает заметки и не создаёт строку
в дереве. Исторический active-item, указывающий на Notes, восстанавливает Overview
соответствующего проекта. Не удаляем файл заметок при миграции или закрытии вкладки.

Обновить все точки входа: клик по проекту, открытие Markdown из MCP и ссылок,
переходы из файлов агента, pause/close и восстановление приложения. Автосохранение,
конфликты и проверки актуального владельца документа сохраняют текущие контракты.

## Обнаружение IDE

Стартовый каталог: VS Code, Visual Studio, Rider, Cursor, Windsurf, Zed,
IntelliJ IDEA, WebStorm и PyCharm. Это предложение исполнителя для первого этапа.

Искать установленные приложения через известные записи Windows, PATH и типовые
каталоги, включая JetBrains Toolbox; не обходить весь диск. Учитывать пользовательские
и машинные установки, объединять совпадения одного приложения по пути EXE.
При разных установках/каналах допускается несколько различимых кнопок.

Значки извлекать из найденных установленных приложений и кешировать в памяти.
Название в подсказке остаётся доступно при ошибке чтения значка. Обнаружение
не должно блокировать UI и не запускает саму IDE. Проверка запускается при первом
открытии Overview, результат общий для проектов; предусмотреть повторное обновление.

Кнопка открывает текущий каталог либо подходящий solution средствами IDE;
аргументы передаются структурированно через существующую границу запуска процессов.
Выбор solution при неоднозначности остаётся решением реализации, но не должен
молча открывать произвольный solution. Командные строки запуска в агентский MCP
для этой функции не передаются.

## Проектные ссылки через MCP

Предложение исполнителя: ссылки принадлежат проекту, сохраняются вместе с ним,
переживают перезапуск и закрытие создавшей их сессии. Это отличается от агентских
файлов, которые принадлежат сессии, и соответствует месту ссылок в Overview.

Добавить обычным проектным сессиям:

- `pact_add_project_link`: `title`, `url`, необязательный `kind`.
- `pact_list_project_links`: текущие ссылки своего проекта.

Типы: `ci`, `merge_request`, `issue`, `other`; по умолчанию `other`. Разные адреса
одного типа могут сосуществовать. Повтор того же нормализованного URL обновляет
название/тип и поднимает ссылку вверх. Это текущий список, без истории событий.
Добавление сохраняет ссылку и не открывает браузер автоматически.

Принимаются HTTP(S)-адреса; удалённую страницу ради проверки или извлечения
названия не загружаем. Проект определяется токеном вызывающей сессии, а не
переданным произвольным project id. ROOT не имеет проектного владельца для этого
инструмента. Инструменты оркестратора в первом этапе не расширяются.

Пользователь может открыть, скопировать адрес или удалить ссылку из Overview.
Открытие использует проектную браузерную вкладку Pact и переиспользует уже
открытую вкладку с тем же адресом. Поведение открытия/удаления не останавливает
сессию и не меняет содержимое внешней системы.

Для ограниченного роста списка предлагается максимум 50 ссылок на проект.
При заполнении добавление нового адреса возвращает понятный отказ, обновление
существующего остаётся возможным; старые ссылки автоматически не удаляются.
Это эксплуатационное решение исполнителя, а не требование пользователя.

Обновить публикуемую агентам краткую MCP-инструкцию: созданные/полученные ссылки
на ревью, задачи и сборки следует добавлять этим инструментом. Записи не утверждают,
что сборка прошла или MR готов: агент передаёт только адрес, название и тип.

## Границы первого этапа

В этом этапе меняется экран проекта. Глобальный дашборд приложения и общий выбор
экрана после закрытия/паузы остаются следующей частью исходного пункта бэклога.
Выбранные Overview и Docs должны корректно восстанавливаться текущим механизмом
перезапуска; перенос документов не должен регрессировать новое восстановление.

Существующие шаблоны веб-ссылок и поля GitLab/TeamCity продолжают работать в своих
старых местах. Новые ссылки агентов не требуют их заполнения. Автопоиск MR/Issue,
опрос статусов CI, канбан и история событий в этот этап не входят.

## Проверяемый результат

- Новые вкладки и встроенные Notes используют сохранённые пользовательские тексты;
  старый notes active-item корректно мигрирует, отдельной строки/кнопки нет.
- Из Overview и Docs можно перейти в живой терминал и обратно с корректным
  autosave, выбором Markdown, конфликтами и поздними асинхронными ответами.
- Найденные IDE появляются с логотипами, отсутствующие не предлагаются; запуск
  использует правильный проект и корректные аргументы для путей с пробелами.
- MCP-ссылка видна в нужном проекте, сохраняется после закрытия сессии и рестарта,
  повтор обновляет её, ручное удаление сохраняется; ROOT и чужой владелец отвергаются.
- Активные ревью отражают существующий relay, изменения остаются справа.
- Ограниченные по ресурсам .NET-сборки и тесты по AGENTS.md; для native UI — отдельный изолированный
  профиль, установленное приложение не заменять и не перезапускать.
