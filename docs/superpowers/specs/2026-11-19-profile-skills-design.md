# Каталог skills и настройки профилей

Карточки #4 и #5. Первый выпуск охватывает настроенные профили Codex и Claude. Поддержку других агентов можно добавлять по мере проверки их возможностей.

## Каталог и установка

Pact читает skills из выбранного командного репозитория и из `~/.agents/skills`. Пользователь может добавить skill по ссылке на публичный GitHub-репозиторий или его подпапку. До установки он видит источник, содержимое пакета, включая скрипты, каталог назначения и профили, которые обнаружат новую установку.

Для Git-установки Pact запоминает репозиторий, путь внутри него, отслеживаемую ветку или релиз и установленную ревизию. Один репозиторий может поставлять несколько skills. У ручной установки источник обновлений может отсутствовать. Привязку к источнику пользователь подтверждает явно. При совпадении имён Pact показывает оба пути и сохраняет существующие файлы до разрешения конфликта.

## Профили и проекты

В настройках профилей пользователь видит фактическую доступность skills и выбирает набор по умолчанию. В проекте для каждого профиля и skill доступны три режима — наследовать, включить, отключить. Наследование учитывает последующие изменения профиля. Рядом с выбором показаны итоговая доступность и её причина.

Набор профиля по умолчанию действует при обычном запуске соответствующего агента из терминала. При общей нативной конфигурации нескольких профилей Pact показывает их связь. Редактор показывает затронутые файлы и профили. Только после команды «Применить» он записывает выбранные настройки skills, сохраняя остальные настройки пользователя. Просмотр каталога и запуск сессии оставляют глобальную конфигурацию без изменений.

Для Claude проектные исключения применяются через локальные настройки проекта и действуют при запуске из терминала. Для Codex проектная папка добавляет skill и при прямом запуске. Чтобы скрыть унаследованный skill, Pact передаёт при запуске Codex параметр `-c` с правилом `skills.config` для абсолютного пути к пользовательскому `SKILL.md`. Интерфейс показывает для этого исключения область действия «При запуске через Pact». При замене skill проектной версией правило скрывает только пользовательский путь. Уже запущенные сессии сохраняют свой набор до следующего запуска.

## Диагностика и границы поддержки

Экран профиля показывает, какой CLI найден, его версию, необходимые зависимости, используемые каталоги skills и действия для исправления обнаруженных проблем. Результаты проверки запуска, восстановления и связи с MCP отображаются по фактическим наблюдениям. До проверки экран показывает «Не проверено». Запуск для проверки открывает видимую сессию.

До реализации редактора наборов проверить каждый режим обычным запуском поддерживаемых версий Codex и Claude. В частности, проверить выключение пользовательского skill в одном проекте и включение в одном проекте skill, выключенного по умолчанию. Для двух профилей одного агента проверить как раздельные, так и общие настройки. Неподдерживаемая операция должна быть видна с объяснением причины.

### Результат проверки CLI от 19 ноября 2026 года

В двух временных Git-проектах проверены два тестовых skill из изолированного пользовательского профиля. По умолчанию виден первый skill, а второй выключен. В одном проекте заданы обратные настройки.

* Claude Code 2.1.318 при инициализации показал первый skill в обычном проекте и второй в проекте с переопределением через `skillOverrides` в `.claude/settings.local.json`.
* В Codex CLI 0.169.0 команда `codex debug prompt-input` показала первый skill в обоих проектах. Глобальное правило по имени в `CODEX_HOME/config.toml` сработало. Проектные правила по имени для skills из `CODEX_HOME/skills` не дали ожидаемого переключения. Отдельная контрольная инструкция подтвердила загрузку проектной конфигурации. Поведение для настоящего пользовательского `~/.agents/skills` требует отдельной проверки.

Проверка касается обнаружения skills при старте CLI. Обе команды выполнены вне Pact без запроса к модели.

Дополнительный опыт с настоящим пользовательским `~/.agents/skills/archify` и временным проектным skill подтвердил локальное подключение в Codex. Проектный skill появился только в проекте с его папкой `.agents/skills`. Пользовательский `archify` остался в списке в обоих проектах после добавления проектного правила `enabled=false` по абсолютному пути к его `SKILL.md`. Такую попытку скрыть унаследованный skill нельзя показывать как успешную.

Контрольный запуск с тем же абсолютным путём в параметре CLI `-c` скрыл `archify`. В опыте с двумя одноимёнными skills Codex перечислил оба пути. Правило запуска по пути скрыло только указанную копию, а правило по имени скрыло обе.

В доверенном Git-проекте с Codex 0.169.0 добавили в `.codex/config.toml` контрольную инструкцию и правила `enabled=false`. В первом опыте правило указывало абсолютный путь к проектному `SKILL.md`, во втором два правила указывали имена проектного и пользовательского skills. Прямой запуск `codex debug prompt-input` в обоих опытах показал контрольную инструкцию и оба skills. Во втором проекте контрольная инструкция и проектный skill отсутствовали. При повторе с аргументами Pact изменились только выбранные пользователем skills. Поэтому Pact не переносит правила из проектного TOML в аргумент запуска. Для правил, которые Codex принимает из пользовательского TOML или из `-c`, восемь комбинаций имени, пути и порядка подтвердили, что побеждает последнее подходящее правило.

Проверка аргументов и окружения, сформированных реализацией Pact, подтвердила обе стороны наследования. В изолированном профиле по умолчанию был виден A. После отключения A и включения B для одного проекта Claude увидел там B как при прямом старте, так и с настройками Pact. Codex увидел B с аргументами Pact и A при прямом старте. Во втором проекте обе CLI сохранили A. У Codex при совпадении нескольких правил действует последнее, поэтому порядок правил при редактировании существенен.

## Обновления

По команде пользователя Pact проверяет Git-источники, показывает доступные ревизии, release notes при наличии, изменения файлов и затронутые подключения. Обновление применяется после подтверждения и сохраняет наборы профилей и исключения проектов. Локально изменённая копия требует разрешения конфликта. Отмена оставляет текущую установку доступной.

## Сквозная приёмка

Установить skill из командного репозитория, включить его в профиле и проверить прямым запуском агента. Отключить skill в одном из двух проектов. Проверить оба проекта запуском из Pact и из терминала: у Claude исключение действует в обоих случаях, у Codex при прямом запуске сохраняется пользовательский набор. Затем поменять набор профиля и проверить наследование и явные исключения. Обновить тот же skill из Git с предварительным просмотром изменений и повторить проверку доступности. Отдельно проверить импорт публичного skill и обнаружение ранее установленного вручную.
