## Итог обсуждения (2026-10-12)

Из спецификации откладывается только часть про хуки. Причины: статус на
регулярках почти не ошибается; полноценные хуки есть только у Claude;
экранный классификатор всё равно остаётся запасным путём и требует
поддержки. Сбои доставки в основном в сценариях — их нужно рефакторить
отдельно.

В работу идут стилизованный снимок экрана и адаптация структурных эвристик
AO (разделы «Rendered screen contract», «Composer interpretation»,
«Heuristic changes»). Главная цель — надёжно определять пустой composer:
механизм доставки уже опирается на этот признак, но сейчас почти всегда
получает Unknown. Раздел «Native hook connection», правила редьюсера про
хуки и соответствующие проверки из спецификации убрать или пометить как
отложенные.

Замечания ниже про хуки — справка на случай, если к ним вернутся.

## Разделить спецификацию на три задачи

Сейчас в одной спецификации смешаны три задачи с разными целями:

1. **Хуки → статус.** Агент сам сообщает «начал ход», «ждёт пользователя»,
   «закончил ход». Это уточняет индикатор вкладки и не зависит от остального.
2. **Стилизованный снимок экрана → пуст ли composer.** Нужен в первую очередь
   для допуска к отправке (dim-подсказка против настоящего черновика), а не
   для индикатора.
3. **Подтверждение отправки** (сопоставление записи с `UserPromptSubmit`).
   Это задача контракта доставки.

Решение: п. 1 отложен, п. 3 уходит в задачу доставки и рефакторинга
сценариев. В этой спецификации остаётся п. 2 вместе с адаптацией
структурных эвристик AO.

## Уточнения к части про хуки

### Транспорт

- **Не вызывать основной exe Pact на каждое событие.** Строки 98–101
  спецификации предлагают «stable Pact executable command», обрабатываемую
  до старта Avalonia. Это лишний холодный старт большого приложения на
  каждый хук. Варианты по предпочтению:
  - HTTP-хуки Claude, если они есть в 2.1.295: процесса нет, токен из env
    в заголовке;
  - отдельный NativeAOT-пересыльщик (`Pact.HookForwarder.exe`) без Avalonia,
    без process lease и без .NET runtime: читает stdin, берёт адрес и токен
    из env, делает один POST на loopback с коротким таймаутом, всегда
    выходит с кодом 0. Минимум нужен для Codex (только command-хуки).
  - `curl.exe` не подходит: подстановка env с токеном зависит от оболочки,
    которой агент запускает хук.
- **Явный `timeout` в объявлении хука.** У Claude по умолчанию 600 с. В AO:
  30 с для Claude, 5 с для Codex.
- **Не подписывать `PreToolUse`.** Он синхронный и вызывается на каждый
  инструмент. Для статуса хватает `UserPromptSubmit`; для снятия запроса
  разрешения — `PostToolUse` с тем же `tool_use_id`. Где поддерживается —
  `"async": true`.
- **Стабильный путь к пересыльщику.** Разные пути у dev-сборки и
  установленной копии заставят Codex заново спрашивать доверие для каждого.

### Доверие к хукам Codex

AO (`adapters/agent/codex/codex.go:515`): хуки из `-c` не имеют сохранённого
хеша доверия в `[hooks.state]`, и без `--dangerously-bypass-hook-trust`
Codex «задерживает их до интерактивного просмотра хуков». Спецификация
выбирает обычный поток доверия. Проверить на 0.162.0 до реализации:

- появляется ли просмотр хуков как диалог при старте TUI (перехватит первую
  отправку, в том числе в свежей сессии сценария);
- сохраняется ли одобрение для `-c`-хуков между запусками при стабильной
  команде. Если да — Codex сам пишет его в `~/.codex/config.toml`; оговорить
  это относительно правила «не трогаем глобальный конфиг»;
- что видит пользователь, если не одобрил: нужна видимая подсказка, а не
  только «unconfirmed» в диагностике.

Заранее решить запасной путь: bypass по настройке или Codex без хуков.

### Порядок, повторы, дубли

- Процессы хуков работают параллельно, события приходят в произвольном
  порядке. Метку `observedAt` ставит пересыльщик; редьюсер упорядочивает по
  ней, а не по времени прихода.
- Пересыльщик не повторяет отправку при транспортной ошибке (иначе `Stop`
  применится дважды). AO повторяет только при явном ответе «не применено».
  Либо приём идемпотентный по ключу (поколение, событие, `tool_use_id`/`turn_id`).

### Семантика событий

- **`Stop` не всегда конец хода.** Если пользовательский Stop-хук вернул
  `decision: block`, Claude продолжает (`stop_hook_active` в payload).
  Unread completion (правило 8) отмечать, только если после `Stop` нет
  нового прогресса, либо учитывать `stop_hook_active`.
- **`SessionStart`**: matcher `startup|resume|clear|compact|fork` (с одним
  `startup` после `--resume` теряется id сессии, AO #4122). `session_id`
  отсюда позже можно использовать для актуальной resume-команды, в том числе
  после `/clear`.
- **`SessionEnd`** с `reason=clear|resume` — не выход.
- **Запрос разрешения и вопрос** в UI — один статус «ждёт ответа
  пользователя». Различается только условие снятия: разрешение снимается
  `PostToolUse` с тем же `tool_use_id`, вопрос — следующим
  `UserPromptSubmit` или прогрессом.
- **`Notification` Claude**: `permission_prompt`, `agent_needs_input`,
  `elicitation_*` → ждёт пользователя; `idle_prompt` приходит примерно через
  минуту простоя и годится только для восстановления пропущенного `Stop`.
  У Codex `Notification` нет: вопросы у него по-прежнему только по экрану.
- **Субагенты.** Сейчас родитель, ожидающий субагентов, корректно Busy; это
  сохранить. Тест «родитель ждёт субагентов → Busy»; `SubagentStop` и `Stop`
  дочернего агента не означают конец хода родителя.

### Диагностика

- Ошибки пересылки агенты не показывают (stderr хука глотается). Счётчик
  ошибок в деталях вкладки; лог только метаданных с ограничением размера
  (у AO `hooks.log`, 1 МБ).
- Признак «хуки настроены, но не работают»: был локальный Enter, а
  `UserPromptSubmit` не пришёл.

## К задаче доставки (вне этой спецификации)

- Сопоставление отправки и `UserPromptSubmit` — общее для всех каналов, не
  завязано на содержимое запроса (имена task-файлов и т. п.): короткоживущая
  запись «ожидаем отправку» с хешем нормализованного текста и поколением
  запуска; хеш `prompt` из хука считается так же. Текст не логировать.
  Проверить совпадение `prompt` с записанным для переводов строк, bracketed
  paste, свёрнутых вставок Claude `[Pasted text #1 +N lines]` и посимвольной
  вставки Codex; где не совпадает — объявить сопоставление неподдерживаемым.
- У Claude хуки не выполняются до доверия к папке; если подтвердится, первый
  `SessionStart` — признак, что диалог доверия пройден.
- Codex при близком лимите показывает на старте диалог смены модели, который
  съедает первый промпт; AO подавляет его
  `-c notice.hide_rate_limit_model_nudge=true`.
- `last_assistant_message` из `Stop` может заменить вырезание последней
  реплики с экрана для оркестратора.
