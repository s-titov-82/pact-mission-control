# PACT:> Mission Control

[English](README.md) | [Русский](README.ru.md)

PACT:> Mission Control — это настольный центр управления для Windows, который
собирает в одном месте терминалы агентов разработки, контекст проектов,
документацию и рабочие ссылки.

![Главное окно PACT:> Mission Control с демонстрационным проектом и терминалом PowerShell](docs/images/main-window.png)

![Окно настроек PACT:> Mission Control с демонстрационным профилем запуска](docs/images/settings-window.png)

## Возможности

- Запускает видимые сессии Codex, Claude, Hermes, PowerShell и произвольных
  терминальных программ через встроенные Windows ConPTY и xterm.js.
- Не останавливает работающие сессии при переключении между терминалами,
  Markdown-документами, заметками и браузерными вкладками WebView2.
- Предоставляет явные действия для промптов, выделенного текста, Git и
  фиксированного цикла автор/ревьюер, не превращая подписочные TUI-инструменты
  в скрытый API.
- Позволяет агентам в видимой сессии запросить ревью, прочитать или изменить
  Notes с проверкой ревизии и открыть браузерную вкладку.
- Поддерживает закреплённый оркестратор Hermes: он может показывать состояние
  всех видимых агентов, управлять активными ревью, работать с Notes запущенных
  проектов и сохранёнными веб-вкладками, а также передавать статус, пока
  рабочая станция заблокирована.
- Хранит проекты и вложенные сессии в одном выбираемом каталоге данных.
- Поддерживает постоянные, не связанные с проектом терминалы и браузерные
  вкладки ROOT с отдельными командами Pause и Resume.
- Открывает HTTP(S)-ссылки из терминала как сохранённые вкладки того же проекта
  или ROOT, принимает точные пользовательские URL и сохраняет порядок вкладок.
- Следит за настроенными загруженными веб-страницами, даже когда они скрыты.

PACT:> работает только в Windows. Поддерживаемый пакет —
зависимый от установленной среды .NET (`framework-dependent`) `win-x64`;
отдельной кроссплатформенной версии нет.

## Требования

Для ручного запуска готового релиза из переносимого ZIP нужны:

- Windows 11 x64;
- [.NET 10 Runtime x64](https://dotnet.microsoft.com/download/dotnet/10.0);
- [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/).

Установщик проверяет наличие обеих сред и перед установкой PACT предлагает
доставить недостающие. При использовании установщика ставить их заранее не
нужно; интернет потребуется только для загрузки отсутствующего компонента.

CLI-инструменты агентов в поставку не входят. Установите каждый CLI, который
хотите использовать, и убедитесь, что его команда доступна через `PATH`.
Стартовые профили вызывают `codex`, `claude`, `hermes` и `pwsh`, поэтому
встроенному профилю PowerShell также нужен PowerShell 7.

Для сборки из исходников дополнительно нужны .NET 10 SDK, Node.js 22 или новее
и PowerShell 7.

## Установка релиза

Скачайте установщик и `SHA256SUMS.txt` из
[последнего релиза](https://github.com/s-titov-82/pact-mission-control/releases/latest).
Перед запуском сравните SHA-256 установщика:

```powershell
Get-FileHash .\pact-mission-control-0.1.1-win-x64-setup.exe -Algorithm SHA256
```

Запустите установщик и следуйте его подсказкам. PACT устанавливается для
текущего пользователя в `%LOCALAPPDATA%\Programs\Pact Mission Control`, ярлык
добавляется в меню «Пуск», а ярлык на рабочем столе можно включить отдельно.
Установка и удаление приложения не удаляют данные из `%APPDATA%\Pact`.
Для обновления запустите установщик новой версии поверх текущей; заменить более
новую версию старой установщик не позволит. Перед обновлением штатно закройте
PACT, чтобы живые агенты не завершались во время замены файлов.

ZIP остаётся переносимым вариантом для ручной установки. Сначала установите
две среды из списка выше, распакуйте архив в доступный для записи каталог и
запустите `Pact.App.Avalonia.exe`.

Первые публичные релизы могут не иметь подписи Authenticode, поэтому Windows
SmartScreen способен показать предупреждение. Как проверить контрольную сумму,
аттестации GitHub и SPDX SBOM, описано в разделе
[Проверка релиза](docs/release-verification.ru.md).

## Первый запуск

1. Запустите PACT из меню «Пуск» (или `Pact.App.Avalonia.exe` из ZIP).
2. Нажмите `+` рядом с `PROJECTS` и выберите каталог репозитория.
3. Добавьте терминальную сессию из карточки проекта, выберите профиль запуска
   и запустите её.

Для общей сессии Hermes, панели наблюдения или командной оболочки, не
привязанных к репозиторию, используйте действие `+` в развёрнутом разделе
`ROOT`. Браузерная вкладка добавляется действием `@`. Новые терминалы ROOT
запускаются в каталоге профиля текущего пользователя Windows.

По умолчанию PACT:> хранит постоянные настройки в `%APPDATA%\Pact`. Для
изолированной проверки можно указать абсолютный каталог:

```powershell
.\Pact.App.Avalonia.exe --data-root C:\Pact-Test
```

Один каталог данных может одновременно принадлежать только одному процессу.

Полный пользовательский маршрут приведён в
[руководстве пользователя](docs/guide/ru/README.md).

## Подсказки Pact внутри сессий агентов

При запуске или восстановлении терминала Codex или Claude Pact сохраняет
выбранную команду профиля и добавляет короткую инструкцию текущей сессии. Она
указывает на принадлежащие Pact материалы в `Temp/Retained/PactSkills`;
подробный текст читается только при необходимости и не добавляется в каждый
промпт.

Если функция управления агентами (agent control) включена, поддерживаемая
сессия также получает временное подключение к локальному MCP-серверу Pact.
Приложение не изменяет глобальные настройки Codex или Claude.

Сохранение Settings перечитывает актуальные сценарии и профили ревью. Если
изменяется набор доступных идентификаторов, уже подключённые агенты получают
уведомление об изменении списка MCP-инструментов; перезапуск терминала не
нужен. Прямые внешние изменения файлов вступают в силу только после этой
границы перезагрузки Settings либо после перезапуска приложения.

## Сборка из исходников

```powershell
dotnet tool restore --disable-parallel
dotnet restore Pact.slnx --disable-parallel --locked-mode
dotnet build Pact.slnx --no-restore -m:2 -nr:false -v q -p:BuildInParallel=false
```

Node.js требуется полному набору поведенческих тестов терминального хоста, но
не готовому приложению. Эти команды только собирают дерево исходников. Полная
матрица тестов, нативные Windows-проверки, проверка пакета и процедура выпуска
для сопровождающих описаны в [Development](docs/development.md).
